## §Access
- **curl/WebFetch = 403** (771-byte body, even with a Chrome UA; re-confirmed #397). If an orchestrator says "Immowelt is curl-fetchable", test it with one call, then escalate. ⇒ Immowelt always needs the stealth driver, but under `Parallel: yes` that is NOT `NEEDS-BROWSER`: spawn your OWN driver process with `IP_SAVE_STATE=false` (next bullet). #871 (Parallel: yes) ran clean in one call. *Why:* the old "Parallel ⇒ NEEDS-BROWSER" rule bounced every Immowelt listing back for nothing.
- **Default first move: drive the stealth Firefox from a node script, not the MCP** (17/17 clean runs 2026-08-15 to 09-12, `blocked=false`, ~40–60 s, 616–685 KB `innerHTML`; in `modes/evaluate.md` since 2026-09-12). Spawn it the way `scripts/scan.mjs` does:
  `spawn('bash',['scripts/invisible-venv.sh','scripts/invisible-driver.py'],{cwd:ROOT, env:{...process.env, IP_HEADLESS:'true', IP_LOCALE:'de-DE', IP_TIMEZONE:'Europe/Berlin', IP_STORAGE_STATE:'tmp/browser-state.json', IP_SAVE_STATE:'false' /* read-only: several evaluators may run drivers in parallel (2026-09-28) */}, stdio:['pipe','pipe','inherit']})` → wait for `{ready:true}` → write `JSON.stringify({cmd:'eval', url, snippet})+'\n'` → reply `{ok, result, blocked}`.
  - `snippet` must be a bare EXPRESSION, e.g. `({title:document.title, text:document.body.innerText, html:document.documentElement.innerHTML})`. Not an arrow function: the driver wraps it in `() => (…)`, so a function comes back as `result:null` (#786), which looks like an empty page.
  - The driver emits a second `{"ok":true}` line after the result: write the first non-`ready` message to a file, then `quit`, or the second line overwrites it. Wrap it in your own `setTimeout` kill so a stall fails fast.
  - Two Bash calls: (1) the fetch writes `innerText` + `innerHTML` into `tmp/eval/{NNN}/`; (2) `node tmp/eval/{NNN}/mine.mjs` mines them offline. **Miner in a `.mjs` FILE, never `node -e '…'`**: the escaping level varies per page and the shell/JS quoting layers eat backslashes, so every key comes back NOT FOUND (#670).
  - A deleted exposé comes back via this path too (§Liveness), so it settles aggregator-EXPIRED questions on its own.
- **DataDome wall can come back as `ok:true, blocked:false` — test for it yourself after every fetch.** #908/#909 (2026-10-07): `document.title` "immowelt.de", `innerText` 0 chars, `innerHTML` ~1,5 KB = `var dd={…'host':'geo.captcha-delivery.com'…}` + `<iframe title="DataDome CAPTCHA">`; the driver's `is_blocked()` only matches CAPTCHA text in title/body. Rule: `innerHTML` contains `captcha-delivery.com` OR `innerText.length === 0` → blocked, whatever the flag. Since the 2026-10 driver update it can also come back `blocked:true` with an empty result (#920/#921; 2026-10-14 three parallel workers twice each): treat both shapes the same. One retry (it carried the same DataDome `cid`, so more retries in the same run won't help), then `NEEDS-BROWSER` (the one exception to "Parallel ⇒ own driver"). **The flag is transient, not a burnt session:** #913/#914, blocked 2026-10-07, opened clean 2026-10-08 on the same read-only driver and `tmp/browser-state.json`; so a DataDome `NEEDS-BROWSER` gets one plain retry next cycle before an exclusive browser run or re-seeding trust. Same-morning search pages DataDome-blocked on every transport = detail pages will be too. *Why:* a 0-char page reads like a deleted exposé and the miner reports "no `__UFRN_LIFECYCLE_SERVERREQUEST__` anchor", inviting a false EXPIRED (§Liveness: decide on the phrase, never on length).
- **DataDome fallback = the debug Chrome over CDP, one call.** If `curl -s 127.0.0.1:9222/json/version` answers: a node `.mjs` with `chromium.connectOverCDP('http://127.0.0.1:9222')` → `browser.contexts()[0].newPage()` → `goto(url,{waitUntil:'domcontentloaded'})` → wait 6 s → evaluate the same `{title,text,html}` expression → `page.close()` + `browser.close()` (only disconnects). Clean first try every time so far (#920–#923, #945–#949), ~650 KB. *Why:* CiC needs 4–6 calls because of the ~1 KB cap.
  - **Who runs it:** `Parallel: no` → the evaluator. `Parallel: yes` → NEVER the worker (shared logged-in browser): return `NEEDS-BROWSER`, or the orchestrator pre-fetches via `scripts/cdp-dump.mjs <url> tmp/eval/{NNN}/cdp/` (own tab, clicks "mehr anzeigen", writes `page.txt` = innerText, `page.html` = `page.content()`, `meta.json` = finalUrl/title/JSON-LD/img URLs, prints `{chars, blocked}`).
  - **Working from a `cdp/` dump:** verify identity first (`meta.json.finalUrl`/`title` vs the given URL, and the payload's Online-ID). `page.html` carries the full `__UFRN_LIFECYCLE_SERVERREQUEST__` payload; the standard miner works unchanged (name it `.cjs` if it uses `require`; the repo is `"type":"module"`). Gallery `mms.immowelt.de/*.jpg` URLs download with plain curl (WebP #946, JPEG #1038: branch on `file`) even while DataDome blocks the exposé, so photos are never a reason for `NEEDS-BROWSER`. **Collect the photo set from the whole `page.html`, not the carousel:** `data.classified` can lack any `medias`/`gallery` key, and only the first 3 slides (`aria-label="N von 8"`) carry an `<img src>`. Take the unique `mms.immowelt.de/…/{uuid}.jpg` URLs, drop the one repeated ~7× (Anbieter/contact image) → equals the slide count (#1038: 8). *Why:* grepping the slides gave 3 of 8. §Liveness applies to the dump exactly as to a driver fetch.
- **Skip the invisible-playwright MCP tier.** `new_page` hangs for the full 1800 s idle timeout (#538) or crashes with "Connection closed while reading from the driver"; it worked once (#310), but each hang burns 30 minutes.
- **CiC is the last fallback:** `tabs_context_mcp{createIfEmpty:true}` → `tabs_create_mcp` → `navigate` → `javascript_tool`. No consent wall. The ~1 KB cap means 4–6 calls (900-char head, 2–3 body slices, one regex sweep). If the first `navigate` lands on chrome://newtab, navigate again.

## §Liveness — EXPIRED
- **Deleted exposé = HTTP 200 shell with no payload.** Decide on `Anzeige gelöscht|nicht mehr verfügbar` in `innerText` (+ a bare `document.title`), NEVER on length. Variants: `document.title` "Immowelt", ~540 chars, "Anzeige gelöscht — Diese Anzeige wurde bereits gelöscht" (#542); Online-ID URL (`/expose/26IN6Z1991TC`): title = the bare Online-ID, ~3,1 KB "Diese Anzeige ist nicht mehr verfügbar" + ~25 foreign "Mehr Angebote wie dieses" cards (#905). *Why:* the old `L < ~1000` test missed it, and the cards read like the listing's own price/m²/Ortsteil.
- **Lister-declared VERGEBEN:** page complete and live, `isNew:true`, but the headline reads "TAUSCHWOHNUNG VERGEBEN: …" (#712). Sweep `vergeben|bereits vergeben|nicht mehr verfügbar|reserviert` (case-insensitive) over `sections.mainDescription.headline` + `classified.title` + `document.title` together: on the swap feed `classified.title` holds the DESCRIPTION and the headline lives only in `mainDescription.headline` (#719, #779); `classified.title` can be `undefined` (#730), so use `String(d.title)`. `metadata.updateDate` = the day the title was edited.

## §Payload — parse the embedded record, don't scrape
The extraction recipe (UFRN anchor, optional `;`, `app_cldp`/`app_demand_referral_cldp`) is in `modes/evaluate.md` → Browser & portal quirks → Immowelt. Extra traps:
- **Slicing, not regex:** `indexOf` the BARE key (`zipCode`, not `'"zipCode"'`, #671). Never regex `"key":"value"`: escaping is 1×–3× per page (#660), one unescape pass is not enough.
- **Null-guard every optional section:** `sections.features` can be `null`, plots have no `energy`, swap ads can lack `rawData.tags`.

**Field map of `d` (`classified`):**
- `metadata.{legacyId, creationDate, updateDate, isNewBuildProject}`
- tags in `d.tags` and/or `d.rawData.tags`, varying key set (`has3DVisit, hasBrokerageFee, isNew, hasFloorPlan, hasVirtualTour, hasVideo`); absent entirely on some swap ads (#710, #711): run `Object.keys()` first.
- `rawData.{distributionType, propertyType, propertySubType, distributionSubType, geoIdHierarchy}`
- `domains.medias.{images, floorplans, videos, virtualTours}`: entries `{url, description, classification?}`
- `sections.location.{address:{street,city,zipCode,district}, isAddressPublished, geometry}`
- `sections.hardFacts` (facts[], price, `titleAdditions`, `locationDescription`) · `sections.price` (base / additional / breakdown: Kalt, NK, HK, Kaution, commissionFee) · `sections.key` (Online-ID + Referenznummer)
- `sections.description.texts[]` = full prose incl. the Stichworte block · `sections.mainDescription.{headline, description}`
- `sections.features.{preview, details}` · `sections.energy` · `sections.documents.files[]` · `sections.priceComparison` · `classified.aiEnrichments`
- `contactSections.contactCard.{title, subtitle, isPrivateOwner, phoneNumbers}`
- **`innerText` tail:** "Über den Anbieter" gives company + `{x},{y}/5 ({N} Bewertungen)` + partnership tenure (Block-H input). The rating is portal-local and won't match IS24's for the same firm (#661: 3,9 vs 3,8): no evidence against a dupe, and neither overrides ProvenExpert/Jacasa. Private ads show "Privater Anbieter / Keine Telefonnummer hinterlegt" (portal contact only, minor caution).

## §Merkmale — features
- **`sections.features.details.categories` is the COMPLETE list**, incl. the chips behind "Alle N Merkmale anzeigen" (#661: `preview` 8 chips, `details` held 3 more incl. `teilweise möbliert`; #671: the hidden tail held `Barrierefrei` + Badewanne). `details:null` = `preview` IS complete (#662). Never click the expander (a `<div>`, does nothing; #397, #632). CiC chip selector: `span.css-qjxbdv`.
- **`sections.features === null`** = the lister never saw an Ausstattungsmaske: must-haves are UNANSWERABLE, not absent → "unbestätigt" + a Next-Steps question (#721). Per ad, not per feed (#722 from the same feed had chips incl. Keller).
- **A complete list is not a feature census.** With fewer than ~3 chips write "not stated", and look for a sibling posting (#660: 1 chip, no Keller; its Tauschwohnung twin #661 had 7 incl. Keller). "Confirmed missing" needs: a complete list + 0 prose/HTML hits + no photo evidence + no known sibling posting + silence in a passage that would naturally mention it (#663).
- **AI-derived chips** are in `classified.aiEnrichments` (`[{icon,value,rawValue}]`) and per chip as `enrichment:"ai"`: machine-derived from the prose, so cite the sentence, not the chip. They can be flatly wrong (#720 "Stellplatz" from public Bewohnerparken); `energy.features` can carry them too (#665 "Fußbodenheizung").
- **Blocker-adjacent chips:** `{icon:"furnished"}` is the one-field möbliert test (#725), can be invisible in `innerText` (#661); same block: `pets-allowed`, `flat-share-possible`. `{icon:"rented", value:"vermietet"}` on a RENT ad (mirrored by `priceComparison.investmentValues[].is_rented:"ja"`) = occupied until the `frei ab` date, not a sale (#765).
- **`Stichworte` is a separate structured line** inside the description (not `Sonstiges`), with facts found nowhere else: Anzahl Schlaf-/Badezimmer, Anzahl Balkone/Terrassen, `Balkon-Terrassen-Fläche` (a SUM), `Mindestmietdauer`. #632 had "24 Monate" while the IS24 twins had no such field: read it even when you have the IS24 record, treat it as probably project-wide. The sum resolves contradictory chips (#730: Balkon + Terrasse chips, sum 21,06 = the terrace alone → no balcony). It can be a typo (#731: 10,52 vs plan 10,25) or copied from a sibling (#789, #828): the plan wins when `rooms + outdoor × {0,25|0,50}` doesn't reproduce the headline area.
- **Keyword sweeps over `innerHTML` are a cross-check only.** On portal-generated fields a 0 count is trustworthy as "not stated"; lister prose has typos that void full-word greps (#666 "Maissonette"): sweep stems (`Maison|Maiss`, `Souter`, `Hochpart`) or read the text.
  - **Split by token class:** acronyms (`WBS`, `EA`, `KfW`, `WG`) case-SENSITIVE (#667: a case-insensitive `WBS` hit CSS class names → phantom hard blocker); compound-tail nouns (`aufzug`, `küche`, `keller`, `balkon`, `garten`, `heizung`, `stellplatz`, `bad`) lowercase stem, case-INSENSITIVE (#671: "Personenaufzug" gave 0 hits for `Aufzug`; so #668's "kein Aufzug" was never established).
  - Verify each hit's context: nav boilerplate contains `Zwangsversteigerung`, Ortsbeschreibungen contain `Denkmal` (#398).
  - Add `hausboot|floating|liegeplatz|auf dem wasser|überführung|schwimmend`: #725 was a floating home listed as APARTMENT/RENT (Ortsteil = current berth only, no Mietspiegel category, implausible Keller chip).
- **Positive Keller proof:** a "Grundriss Keller" media caption (#396).
- **Sparse is real:** a single Merkmal (#596: only `Bezug`) is a sparse listing, not a failed extraction.

## §Energy
Read `sections.energy` / "Bausubstanz und Energie" first. Five shapes; only shape 3 justifies opening the modal. Shapes 2 and 5 both carry `hasScales:true` + an `alternateText`: tell them apart by the sentence, never by `hasScales`.
1. **Deferred:** "Der Energieausweis wird bei Besichtigung nachgereicht/vorgelegt" (#538; #632 under an `Energiepass` heading in Sonstiges) = § 87 GEG omission.
2. **Exempt claim:** "Ein Energieausweis ist für diesen Gebäudetyp nicht notwendig." in `certificates[0].scales[0].alternateText`, no class, no kWh = the § 79 Abs. 4 GEG Baudenkmal exemption, **falsifiable**: `yearOfConstruction` > 1948 → false, a § 87 omission (Low), no EEK bonus in D; prose also quoting an EEK/kWh → add a Medium "exposé internally inconsistent" (#686: Bj 2011, "Klasse C / 76 kWh"). Only with no Baujahr at all: "claimed, unverified", no Missing-EA signal, check the Denkmalliste ([[potsdam-mietspiegel]]) (#539).
3. **Teaser:** class/value snippet + "Mehr Infos". Open `document.querySelector('[data-testid="cdp-energy-modal-button"]').click()`, wait ~1,5 s, read `[role="dialog"]` (kWh, Ausweistyp, Gültigkeit, Energieträger). With the payload, `energy.certificates` already has it.
4. **Lead-gen prompt:** "Möchtest du Details zum Energieverbrauch? → … anfragen" (`data-testid="cdp-energy-info-not-available"`) = certificate missing, not exempt: § 87 omission + Low. Common on private and swap ads. Richer variant `{features:[heatingSystem], hasScales:false}`; poorer: no `energy` object at all (#669) → no Heizungsart anywhere, don't assume "warm = kalt + NK" is complete. Mietspiegel: the "kein EA" row where one exists (bis 1948, 1949–1970); for 1971+ cite the whole EEK band ([[potsdam-mietspiegel]]).
5. **Type declared, no data:** `certificates[0].features = [{type:"basedOn", value:"Verbrauchsausweis"}]` + `alternateText` "Der Anbieter hat keine Daten zum Energieausweis hinterlegt." = a certificate exists but class/kWh withheld: § 87 omission (Low), NOT an exemption. Compare re-lists: #985 had this shape, the same lister's earlier ad (#539) the shape-2 sentence. *Why:* matching on `hasScales` alone silently grants the Denkmal story.
- **`documents.files[]` "…Energieausweis….pdf" can be a 300-dpi scan** (#893: `pdftotext` = 5 bytes): `pdftoppm -r 110 -f 1 -l 1 -png` + Read page 1 (Adresse, Anzahl Wohnungen, Baujahr, Anlass, Registriernummer, Gültigkeit). *Why:* a text-only pass reads "PDF empty" and loses the proof of which building it is.
- **`energy.features` "Baujahr" on a private owner's cross-post can be the modernisation year** (#921: Immowelt 2023, the IS24 twin only `obj_lastRefurbish: 2023` + "Modernisiert", 2000s kitchen/bath in photos). With an IS24 twin, compare; on conflict report the Baujahr as *contested* and compute the Bremse for both readings (§ 556f vs Bremse). *Why:* the Immowelt year at face value silently grants § 556f and deletes the § 556g lever.
- **`energy.features` "Zustand der Immobilie" carries a lister-picked Baualter bucket that can contradict `yearOfConstruction`** (#1057: "Altbau (bis 1945), renovierungsbedürftig / sanierungsbedürftig" next to Baujahr 1982; orange 1980s sanitary ware and pine-panelled Dachschrägen confirmed 1982). Use Baujahr + photos, take only the condition half of the chip, list the contradiction as a contact question. *Why:* at face value it puts a 1982 house into the pre-war class (Mietspiegel row, GEG/Denkmal reasoning, D base).
- **`efficiencyClass.index` is not the GEG class** but Immowelt's 9-segment kWh bar index: derive the class from kWh (#824: index 1 at 86 kWh = C). `validity` can be nonsense (#824 "bis 08.08.2020" on a 2023 Bedarfsausweis): flag it.
- **The summary `Energieträger` can be wrong** (#570: Fernwärme vs prose + modal Öl; modal and prose win). Öl vs Fernwärme moves D and the CO2/Nachzahlung risk.
- **No `Heiz*` hit anywhere** = Immowelt's "Warmmiete" may be Kalt + NK only. Cross-check the IS24 twin's "Heizkosten in NK: Nein" (#632: 85–120 EUR/month decided the warm cap). A high NK/m² is only weak evidence that heating is included (#665: 3,37).

## §Price
- **Always re-add the line items; the labels lie:**
  - A HK row `alt:"nicht in Warmmiete enthalten"` can sit next to a Warm that already equals KM + NK + HK (#783): trust the arithmetic, don't add HK twice.
  - A lister's newer ads can gain a HK row "in Warmmiete enthalten" its older ads lacked (#826 vs #732): report both scenarios rather than switching the batch's assumption.
  - A description total can include an optional extra (#726 "Warmmiete 2.002" = 1.922,45 + an 80-EUR Garage): quote both, ask whether it's mandatory.
  - Prose and Mietkosten can disagree outright (#533: 2.340 vs "2.400"): report both, don't average. Price cuts update the header but leave a "Mietkonditionen" block in Sonstiges stale (#310). `price.additional` Kaution can contradict the description (#725: 2.599 vs "3 Nettokaltmieten").
  - On the swap feed the "Kaltmiete" field (and its €/m²) can be the Warmmiete (#865, prose "1.112,45 € warm"): grep the prose for `warm|kalt` first.
- **Rental `sections.priceComparison`** is only `{hasMainPrice, isSale:false, pricePerSqm, legalText}` (the percentile panel is Kauf-only, [[immowelt-kauf]] §Kauf-Price). `pricePerSqm` uses the lister's `livingSpace`, so a wrong m² gives an authoritative-looking wrong €/m² (#725, #868).
- **`defaultBackToSearch` priceMin/priceMax** is a mechanical ±20 % window around the ask, no information (an earlier "lister's own band" note was refuted 2026-08-23, #664).
- **Provision:** on rentals `tags.hasBrokerageFee:false` settles the Bestellerprinzip; without tags run a case-insensitive `provision|courtage` sweep. (On Kauf the tag lies: [[immowelt-kauf]] §Kauf-Price.)
- **Befristung, Mietlaufzeit and Kaution live in the rental `Sonstiges` tail** ("Mindestmietzeit von 1 Jahr", "auf vier Jahre befristet", #570); no structured field, so regex `befristet` over the prose (the h1 sometimes says it). Score with the plain Befristet rule (not the Zwischenmiete cap) + the § 575 BGB lever (no stated Befristungsgrund → unbefristet). Short private exposés can lack Sonstiges/Stichworte: Mietkosten is then the only Kaution source (#538).
- **Availability** is often only an "Einzugsdatum" field in the contact form: F 3,0 + ask.

## §Size
- **`hardFacts.livingSpace` is free text:** it can be neither Wohn- nor Gesamtfläche (#725: 160 vs prose "220 m² Gesamtfläche, 100 m² Wohnfläche"; grep `Wohnfläche|Gesamtfläche|Nutzfläche`, prefer the labelled Wohnfläche), a 10× typo (#868 "900 m²" → size UNKNOWN, bracket the Mietspiegel), or copied from a sibling unit on project lettings (#789).
- **"Gesamtfläche" in a private ad can span a Souterrain level** (#980 Eiche: "95 m² Gesamtfläche, 3 Zimmer" = the fields, but the two `floorplans[]` (`FP_IMG_*.JPG` screen photos) showed an EG plus a lower level with "Raum 3" behind a Lichtschacht and the ONLY Bad; the "Kellerraum" photo was that room → WoFlV area maybe ~half, 2 Zi, €/m² doubles). On "Gesamtfläche" wording or an internal staircase, check every plan level before scoring C or A, bracket the Mietspiegel for both areas. *Why:* 11,05 €/m² read as an ordinary 95 m² flat at ortsüblich.
- **WG-room ads look like whole-flat listings:** `hardFacts` carry the WHOLE flat while Kalt/Warm/Kaution are the ROOM price, so the €/m² looks like a bargain (#981: 650 / 88 = 7,39). Tells: prose "Mitbewohner", "ein Zimmer frei", "WG-Leben"; chips `möbliert` + `WG-geeignet` (`flat-share-possible`). The `WG-geeignet` chip alone does NOT mean a room ad; the prose decides. *Why:* #981 would have scored as an 88 m² flat 35 % under market. (IS24 analogue: [[immobilienscout24]] §Lease WG-only ads.)
- **`numberOfRooms` rounds to an integer**; the prose is exact (#654: field "3", prose "2,5 Zimmer", straddling min_rooms). Trust the prose, report both.
- **Grundriss reconciliation:** sum the per-room m² and find the outdoor factor that reproduces the headline (#726: 137,62 + 14,60 × 0,5 = 144,92 = the legal maximum, not Flächenschwindel, but the heated-interior €/m² is higher, 11,84 vs 11,25). Plans also reveal Dachschräge `1 m/2 m Linie` markers (advertised = Grundfläche, WoFlV lower), second bathrooms, an absent balcony, an over-stated area (#723: 77 vs 74,84, which moved the Mietspiegel column edge).
- **`documents.files[]` can hold the Bauträger Grundriss as a text PDF:** `curl -A <UA>` the ci_seal URL + `pdftotext -layout` gives the per-room table + SUMME without any image Read (#781). Check it before downloading plan images.

## §Photos
- **`images.length` is not the real-photo count.** Order:
  1. **Dump `images[].description` + `floorplans[].description` first** (the key is `description`, not `caption`/`title`). Professional listers' captions are reliable: "Außenansicht - Visualisierung", "Digital-Home-Staging", a " - (KI generiert)" suffix = virtual staging paired with a real empty-room shot (subtract it; no D cap, no scam signal, #781). Plan filenames identify the unit (`FF26888_…_Haus_1_…_WE_5_…`, #729). `classification` is a GUESS, wrong both ways (#729: brick facade tagged LOGO, team photo COURTYARD; #728: "LOGO"/"ENERGY_CERTIFICATE" were Vonovia banners; #810: HOUSE_FACADE = ad banner, YARD = stock family photo). At minimum subtract LOGO and GMAP (#637: 62 entries vs ~44 real).
  2. **Download what the captions leave ambiguous:** every image without a `classification`, blank or "Bild N" captions (swap feed, allkauf), any gallery ≤ ~8 images.
     - **Tauschwohnung-GmbH feed: download EVERY image, even a gallery of one** (no classification key, #711). A lone "Bild 1" can be the Grundriss (#724 "WE 65.01", #779 "Wohnung 13") = 0 real photos, D cap 3,0; or a watermarked stock placeholder (#778, tell "Fotos gern auf Anfrage") = 0 real, D cap, no scam signal.
     - **`hasFloorPlan:false` + `floorplans:[]` can both lie** (#722: both images were plans; #728 Vonovia Bild 4 = Grundriss with unit id and Loggia anrechnung) — but can be true (#727: 15 real photos). Don't pre-conclude. **Plan position is random** (#726: Bild 3).
     - **A populated `floorplans[]` can be Musterwohnung-only** while the unit plan sits in `images` (the Brauhausberg lister flipped per ad: images-tail on #731/#732/#784/#791/#830, `floorplans[0]` on #785–#790/#792/#793/#826–#829/#831/#832). Sweep BOTH arrays for `FF\d+|WE_\d+|Wohnung_\d+` (#830 `Wohnung_15`).
- **Download recipe:** `curl -s --http1.1 -A <Chrome UA> -H 'Accept: image/avif,image/webp,image/apng,image/*,*/*;q=0.8' -o N.bin "<images[].url verbatim>"` (keep a `ci_seal` param if present; some payloads have none). `file` each download and branch on the BYTES, never the suffix (`.webp` served JPEG #721, `.png` genuine WebP #725): JPEG → `cp` to `.jpg`; RIFF/VP8 → `dwebp`. Plain curl can exit 92/52 on some URLs of a gallery (#722). Shell traps: a URL list without a trailing newline drops the last URL in `while read` (#727); zsh aborts on an unmatched glob (#777), so glob only extensions present; check `ls | wc -l` = `images.length`. Keep images in your own `tmp/eval/{NNN}/imgs/` (a shared dir held stale foreign files, #796). Build `convert … +append/-append -resize 1800x contact.png` and Read it once: Zustand, Bad, Balkon, Keller, Baualter, street signs.

## §Location
- **Resolution order (in evaluate.md):** prose (landmarks, transit lines, named streets) → `zipCode` → street signs / shop names legible in the gallery (#763) → nothing else. Gallery tricks on an address-hidden private ad (#980): a house number on a glazed door reads mirrored from inside ("No.17"); a business across the street (a Subaru dealer) is one WebSearch away; Nominatim both and confirm they face each other (~40 m) → exact derived address. *Why:* it beat `district`, which said "Bornstedt" for Eiche.
- **`district` lies:**
  - Swap feeds: `district:"Grunewald"` + `og:title:"Westend"` is a fallback pair meaning "location unknown" (#655–#658, #683, #696; on #696 `city` lied too: a Siemensstadt flat labelled Charlottenburg-Wilmersdorf). `zipCode` survives only at Bezirk level; a repeated zipCode doesn't make the pair trustworthy. The Tauschwohnung-GmbH feed can be off by a neighbouring PLZ (#902 "Westend" + 10825, prose "Crellekiez, Nähe U Kleistpark" = 10827): the prose decides Kiez and PLZ. Reverse (#983): label "Westend, Berlin (10627)" where 10627 is Charlottenburg and the tauschwohnung NUXT geo agreed with the PLZ → area from PLZ + NUXT geo over the Ortsteil label. *Why:* the PLZ feeds the Address header and the Wohnlage lookup.
  - Potsdam: "Kirchsteigfeld" for an Am-Stern flat (#662; shared PLZ 14480 clears the search group, never the Ortsteil; Mietspiegel differs ~1,6×). "Bornstedt" for Eiche (#672, #980) and for Nauener Vorstadt even with a published address (#985: "Friedrich-Ebert-Str. 60", 14469): with a published street + number, Nominatim the street, never `district` or the map pin. "Fahrland" for a Golm flat (#903; PLZ 14476 shared by Golm/Fahrland/Marquardt; prose "Potsdam, Golm" + a hand-drawn Grundriss naming "Geiselbergstraße"; Fahrland B ~3,5 vs Golm 4,7). The Wohnbau-GmbH Quartier Pappelallee/Voltaireweg is systematically "Bornstedt" while the IS24 API says `jägervorstadt` (#584, #700): with an IS24 twin take `geo_ot`/`obj_regio4` from it.
  - `city` can fail by a same-name Ortsteil collision: #763 "Paaren" resolved to Potsdam's Uetz-Paaren; the plot was in Paaren im Glien (Havelland, 14621, ~19 km out).
- **The lister can disown the address:** grep `Adresse stimmt|stimmt nicht ganz|nicht die genaue Adresse` before writing "PLZ verified" (#654).
- **With `isAddressPublished:true` the `geometry` / Mapbox pin is a `Point` at the geo-id centroid, not the house** (#985: pin reverse-geocoded to Amundsenstraße, Bornstedter Feld; the street is ~3 km away in Nauener Vorstadt). *Why:* it would have "confirmed" the wrong `district`.
- **With `isAddressPublished:false` `geometry` is the Ortsteil MultiPolygon**, from the same geo id as `district`. Useful only when `district` is merely imprecise: point-in-polygon with REAL Nominatim centroids (`nominatim.openstreetmap.org/search?q={Ortsteil}, Potsdam&format=json&limit=1`, ~1 s apart, real UA), iterating ALL rings (discontiguous parts are normal, #673; hand-estimated centroids gave a confident false positive). It adjudicated Eiche vs Bornstedt (#672) and corroborated Waldstadt I on a dupe (#673); it CONFIRMS the error when `district` is the fallback pair (#696) or the city is wrong (#763), and can't resolve a Teillage (#719).
- **A named historic building in the prose** gives address, Baujahr and Sanierung in one WebSearch (#521: Brockessches Palais → Yorckstr. 19/20, 1776, vollsaniert 2016).

## §Identity — dedup
- `Online-ID` is Immowelt-internal; it only dedups Immowelt against Immowelt.
- **Grep `data/listings.md` + `data/pipeline.md` + `reports/` for the Online-ID (case-insensitive) before evaluating.** A row evaluated via an aggregator (SZ, Ab ins Zuhause) records the Immowelt ID only in Notes/report ("cross-posted to Immowelt 267GN4289E5I"), while the scan dedups on the lowercase `/expose/{id}` URL, so the source ad later surfaces as a fresh pending line (#984 = #921). If `updateDate` = `creationDate` (or predates the earlier report) and price/Kaution/captions match: stage `DUPE of #N` + a `tracker_notes` liveness note, no report/TSV. *Why:* otherwise a full duplicate evaluation.
- **Commercial listings:** `Referenznummer` = the lister's own Objekt-Nr., byte-identical across portals, the cheapest cross-portal key (#661 matched #511's IS24 Objekt-Nr.). A ref of ≤ ~4 characters is a row counter (#687 "261"). Project lettings use `H{Haus}-{Etage}-{WE}`: dedup on the full ref, never plan/price/m² (stacked units share a plan, mirror units have identical m²); read each unit's chips and plan on its own (#786 lacked the siblings' Keller chip).
- **Swap feeds:** the Referenznummer is the syndicator's id; dedup rules in [[tauschwohnung]] §Dedup.
- An identical Kalt + NK pair is no dupe signal (#665/#666: both 1.300 + 350, different flats).
- **Aggregator resurfacing:** diff Online-ID + hardFacts + Kaution + photo count; all equal = DUPE of the existing report, not a re-listing.
- **Ad age:** `metadata.creationDate`/`updateDate`, never `isNew` or the "Neu" badge (they track `updateDate` and flip back on any edit; #667: four months online, "Neu"). Long unmatched time is an F/H signal (#666: six months).
  - **Exception — slot-recycling Verwalter:** RBB Immobilien-Verwaltungs-GmbH re-uses one ad slot per flat type (#871: `creationDate` 2020-09-29, `updateDate` = scan day). Tell: type-string Ref `EPS San {Zi}-Zi {m²}` / `EPS San {m²}` (EPS = Erich-Pommer-Straße, Drewitz), always with the §Photos archive disclaimer + "frei werdend" → D cap 3,0 (#513, #871). The old creationDate is then NOT "unlettable for years".
- **"Privater Anbieter" + a GmbH signature in the prose** = a small Hausverwaltung on a private account, not a scam (#539: T&B Grundbesitz, HRB-verified). Resolve via Handelsregister; the Eigentümer is private, so Eigenbedarf risk stays Medium.

## §SwapFeed — Immowelt field quirks of the two swap syndicators
- **Tell:** h1 "… • Tauschwohnung" / `hardFacts.titleAdditions:["Tauschwohnung"]`. Identify the provider from "Über den Anbieter":
  - **Tauschwohnung GmbH** (c/o THE 9TH Bonn, Herr John Weinert): prose opens "Es handelt es sich hierbei um ein Tauschangebot. (Anbieter-ID: N)" (Referenznummer = N), ends with the "Diese Anzeige wurde von einem Nutzer eingestellt … tauschwohnung.com stellt nur die Plattform bereit" boilerplate; `classified.title` holds the description; `documents.files` is `[]`. Completeness varies per ad (sparse #521, rich #533 with 10 Merkmale/NK/Stichworte/19 photos, middling #655, full Merkmale + 1 photo #657): always read Merkmale + Mietkosten before writing "unknown"; Merkmale and photo count fail independently (#657: E 4,5 with a D cap 3,0).
    - **`hardFacts` rooms/m² can be the poster's TARGET, not their flat** (same trap as IS24 #550; #922: facts "4 Zimmer · 90 m²", prose "69 m / 3 Zimmer … weil wir 6 personen sind"). Diff `hardFacts.facts` against the prose: on conflict the prose is the flat, the field the probable Suche, and `pricePerSqm` sits on the phantom area. *Why:* the metadata/TSV would carry the wrong size and €/m², and the Suche half gets lost.
  - **Wohnungsswap.de** (Beedstraße 54, Düsseldorf, Herr Tobias Jonnarth, never a phone): the headline `Wohnungsswap - {Straße}` is real street data (#660); first-person tenant prose, 7-digit Referenznummer; a closing "Wichtig — … bei Wohnungsswap als Tauschobjekt angeboten … im Gegenzug …" paragraph is boilerplate.
