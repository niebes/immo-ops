# Regionalimmobilien24 — page quirks
Portal match: "Regionalimmobilien24" · www.regionalimmobilien24.de

**FASTEST PATH: plain `curl` works.** The detail page is fully server-rendered — `curl -A "Mozilla/5.0 (X11; Linux x86_64; rv:128.0) Gecko/20100101 Firefox/128.0"` returns ~140 KB HTML containing title, location, Etage, Kaltmiete, m², rooms, description, ALL structured blocks (Kosten / Allgemeine Informationen / Ausstattung / Flächen-Räume / Energieausweis / sonstige Angaben), Lage text, image captions and the Objekt-ID footer. Strip tags with a small python3 regex script → ~300 lines of text, everything needed to score. No consent click, no JS, no bot-block on the *detail* page (search/result pages still need a browser for lazy-load). **Why:** the invisible-playwright driver died ("Connection closed while reading from the driver") on 3 consecutive `new_page` calls; curl completed the whole evaluation in one shot. Try curl FIRST for single-listing evaluation, browser only if it 403s.

Bot-blocks headless Playwright. **invisible-playwright (stealth Firefox) works** — reads the full detail-page DOM (incl. the inline wg-listing structured blocks) via `evaluate_script` on `document.body.innerText` WITHOUT clicking the TCF consent dialog; content is already in the DOM behind it. Use it over CiC. (The old "CiC only" note referred to headless-Playwright bot-blocking.)
1. **Consent**: TCF cookie dialog on first load — click "Ablehnen (Funktionseinschränkung)" (privacy-preserving). Remembered in the real browser afterwards, so later runs usually skip it.
2. **Lazy-load**: listing cards only render after scrolling — scroll to the bottom and wait ~3 s before reading; re-read if the result set is empty.
3. **Detail URL/id**: cards are `article#oid-{id}.list-immoitem`; the canonical detail URL is in `.shariff[data-url]`. The region segment in that URL (e.g. `/vogtland/`) may not match the property's town but still resolves by id.
4. **Numbers** on the card are mixed: price/m² German (`1.040,00` / `71,00`), room count dot-decimal (`3.5 Räume`).

Aggregator of the same source pool as Süddeutsche → heavy overlap (cross-portal dedup collapses twins).

## **The URL's id FORM tells you whether you need the source at all — check it first**
Three id forms appear, with very different data completeness:
- **Bare numeric id, `/{region}/mieten/wohnung/{9 Ziffern}/`** (any leading digit — seen `072625535` #605 and `504603417` #646) → **FULL exposé inline, no source hop needed.** Everything is server-rendered on the aggregator: Kosten (Nettokaltmiete/Nebenkosten/"Heizkosten enthalten"/**Kaution**/Stellplatzmiete), Allgemeine Informationen (Objektart, Wohnungstyp, **Baujahr**, Zustand, "Wohnobjekt auf Zeit: ja/nein" ⇒ Zwischenmiete-Check), Ausstattung, Flächen/Räume, **Energieausweis komplett** (Art, Kennwert, Träger, Klasse, Jahrgang), "weitere Informationen" (Verfügbar ab, Denkmalschutz), Lage-Text, "sonstige Angaben" (Anbieter-Kontaktmail + Plattform-Disclaimer) und der Objekt-ID-Footer. There is **no `data-href`** on these pages (only `data-href=""`) — do not go hunting for one. Source is usually **ohne-makler.de**-Syndikation (Text-Disclaimer im Tail, Kontakt-Mail des Eigentümers im Klartext, provisionsfrei, "Makleranfragen nicht erwünscht"). Seen on #605.
- **`wgXXXXXXXX`** (Wohnglück) → mostly inline, but Nebenkosten/Kaution/Verfügbarkeit/WBS fehlen (siehe unten).
- **`imXXXXXXX`** → echte Dünn-Re-Listung, Quelle nötig (siehe unten).

### Three parsing traps in the stripped-text dump (all seen on #646, bare-id page)
1. **`🤖 KI-generierter Inhalt` + `💬 heyRegio – Immobilienassistent` get injected INTO the middle of the structured blocks** — on #646 they landed between `Zustand: Neuwertig` and the `Ausstattung` heading. That is the site-wide chat widget, **not** a listing field and **not** a disclosure that the exposé text is AI-written. Drop those lines; never quote them as an object attribute.
2. **`grep`-ing the raw HTML for `auf Zeit` always hits ≥2 times** — the two nav menus both contain the menu item *"Wohnen auf Zeit"*. The Zwischenmiete check must be done on the **`Allgemeine Informationen` block only**: when the flat is *not* auf Zeit the field `Wohnobjekt auf Zeit` is simply **absent** (you see only `Wohnobjekt ja / Gewerbeobjekt nein / Kaufobjekt nein / Mietobjekt ja`), not `nein`. Absence = normal permanent letting.
3. **The Anbieter block is fully server-rendered, including the phone number that sits behind the "Telefonnummer anzeigen" button** — company name, street, PLZ/Ort, Impressum + Widerrufsbelehrung links and `Tel. zentral: 00493088702407` all come down in the curl body. No click, no browser needed for Block H. (Note the `0049…` prefix form.) The **owner/Vermieter is generally NOT named** on agent listings — only the Makler — so Eigenbedarf risk stays an open question by construction.
   - ⚠ **That only holds for AGENT listings.** On a **private ohne-makler listing the Anbieter block collapses to the bare string `Ohne Makler`** — no name, no street, no phone, only the generic `ohne-makler-net/impressum` link and the contact form ("Diese Immobilie anfragen bei Ohne Makler"). Do NOT keep hunting for an Impressum block that isn't there: this *is* the complete Anbieter data. Score Block H as private owner / unknown, Eigenbedarf **medium**, and put "Name + Eigentümerstruktur" on the Erstkontakt list. (#695.)

4. **Counting photos: dedupe by FILENAME, not by `src`.** Every object photo ships in **two size variants** of the same file (`…/v/399x350/crop/{hash}.jpg.webp` and `…/v/750x600/crop/{hash}.jpg.webp`), and the same `images/immo/` prefix also matches Makler-logo/system assets — so `grep -o 'images/immo/[^"]*' | sort -u | wc -l` returned **9** on a listing that has exactly **ONE** object photo. Cross-check against the `Bild N / {total}` caption in the stripped text, which is authoritative. Getting this wrong flips the Block-D photo-evidence call. (#695.)

5. **Floor is stated twice, in two different counting systems.** The price header says `… | 2. Etage` (German OG count) while the Eckdaten block says `Etage 3 von 3` (physical storey, EG = 1). **Same floor, not a contradiction** — don't report it as a data inconsistency; write it as "3. von 3 Geschossen (= 2. OG), Dachgeschoss". (#695.)

6. **The Energieausweis block can be internally inconsistent — trust the kWh value, not the class label.** Seen: `Energieeffizientsklasse A+` next to `Verbrauchskennwert 70.00 kWh/m²a` (70 is class **B**), plus `Energiepassart Verbrauch` and `Energiepass Jahrgang 2014` on a `Baujahr 2026` Erstbezug — a Verbrauchsausweis is impossible for a new build (§ 80 GEG wants a Bedarfsausweis). The `\/api\/epass\/lg\/{hash}-{Kennwert}.png` filename confirms the kWh figure independently, so it is the reliable number. This is a **private-inserent data-entry artefact, Low-tier scam signal at most — never a High signal**, and it usually doesn't move Block D at all (A+/A/B all give the same +0,5). (#695.)

**Photo count without a browser:** either the `Bild N / {total}` caption in the body text or `grep -oE 'src="[^"]*images/immo/[^"]*"'` — Objektfotos liegen auf `bilder.regionalimmobilien24.de/get-file/img/images/immo/{maklerHash}/{objektId}/…`, Anbieterlogos unter `images/makler/`, alles andere ist `system_ri24/` (Banken-/Team-Deko). Der Energieausweis-Balken ist ein API-PNG `\/api\/epass\/lg\/{hash}-{Kennwert}.png` — der Dateiname trägt den kWh-Wert.

**Dieselbe Wohnung läuft unter zwei Region-Slugs UND zwei id-Formen** (#605: `/vogtland/…/072625535/` = `/havelland/…/wg16917407/`, identischer Preis). Das ist ohne-makler-Mehrfachausspielung → im Scam-Check ausdrücklich **kein** "reposted with different prices"; im Report als Dublette benennen und beide Pipeline-Zeilen mit einem Bericht abdecken.

## `imXXXXXXX` detail page = thin re-list → resolve to source
The `imXXXXXXX/` detail page only carries title, location, Kaltmiete, m², rooms, description, often a single photo. NO Nebenkosten/Warmmiete/Kaution/Energieausweis/Baujahr/Anbieter/floor. Must go to the source for those.
- **Source link**: the visible "zum Objekt" / "Immobilie anfragen" are `<div>`s with no href; the real link is on a hidden `<span data-href="...">` — selector: `[...document.querySelectorAll('span')].map(e=>e.getAttribute('data-href'))`. For the immobilien.de pool it is `https://www.immobilien.de/wohnen/{id}` (same numeric id as `imXXXXXXX`).
- Gallery photo `<img>` src also reveals the source host (e.g. `immobilien.de/srv/obs/.../estate_attachments/{id}/...`).
- **Do NOT guess source URLs** (e.g. `/expose/{id}`) — a wrong navigate triggers a permission-denied prompt. Read the `data-href` first.

## Source pool varies: immobilien.de OR wohnung-jetzt.de OR wohnglueck.de
The `data-href` source host is not always immobilien.de. Seen `https://www.wohnung-jetzt.de/exposee/{id}/` and `https://wohnglueck.de/property/{internalId}` (wg-listings: page footer shows "Objekt-ID intern: {internalId}" = the wohnglück property id; "Objekt-ID extern: wgl-{id}"). Read the `data-href`; don't assume immobilien.de. wohnglueck.de is ALSO access-blocked in this env (navigate → "Permission denied by user"), same as immobilien.de/wohnung-jetzt.de → score from the aggregator's thin data.
- **wg-listings (Wohnglück) embed the FULL gallery inline on the aggregator** as a "Bild N / {total}" captioned list in the body text (e.g. 15 images incl. real room photos + Bestandsgrundriss). Count via the "Bild N / N" captions — condition IS verifiable, do NOT apply the no-photo Block D cap. Structured blocks (Kosten / Allgemeine Informationen / Energieausweis / Ausstattung) are also inline, so Baujahr, Energieausweisklasse+kWh, Heizungsart, Objektart, Stellplatzkosten ARE present. Still MISSING on the aggregator for wg-listings: Nebenkosten/Warmmiete, Kaution, Verfügbarkeitsdatum, WBS, Haustiere → mark "unverified, ask at contact". Anbieter appears as free text in the description tail (e.g. BVBI / Berliner Volksbank Immobilien, www.bvbi.de).
- The inline gallery is NOT always full: some wg-listings carry only **"Bild 1 / 1"** (single image). Always read the "Bild N / {total}" caption rather than assuming a full gallery. The description tail also often carries the real source platform (e.g. "ohne-makler (OM) ist weder Anbieter noch Vermittler…" → private owner via ohne-makler.de, provisionsfrei) and photo disclaimers ("Bei den Bildern handelt es sich teilweise um Beispielfotos").
- **Contradictory Energieausweis is common on wg-listings:** the free-text description may state a class (e.g. "Energieausweis: A", "KfW-Standard 55") while the structured "sonstige Angaben" block says "Energieausweis nicht vorhanden". Normal for an unfinished Neubau — report both, don't treat as a scam signal.

## Env caveat (2026-06): immobilien.de AND wohnung-jetzt.de domain access-blocked
In the immo-ops Chrome env, navigating to `immobilien.de` succeeded but ALL subsequent tool reads returned "Permission denied by user"; `wohnung-jetzt.de` is worse — the `navigate` call itself returns "Permission denied by user". Either way you cannot extract from the source → score from the aggregator's thin data, mark missing fields (Nebenkosten/Warmmiete/Kaution/Energieausweis/Baujahr/Anbieter/floor) "unverified, ask at contact". Not a scam signal — just a data gap.

## Photo gallery IS on the aggregator (don't blindly cap Block D)
The aggregator detail page embeds the FULL source gallery inline as `<img>` (e.g. wohnung-jetzt id wj73270451 showed all 20 real photos as `images.wohnung-jetzt.de/media/client-XXXX/...jpg`, plus a "Bild N / 20" counter in the body text). Count `[...document.querySelectorAll('img')].filter(s=>s.includes('/media/')||s.includes('/import/'))`. When real photos are present, condition is verifiable → do NOT apply the no-photo Block D cap even though the source page is blocked. The older "cap D at 3.0 (1 photo)" advice only applies when the gallery genuinely has ≤0 real photos.
- A bare query-string-touching JS filter (`a.href` containing `?`) also tripped a `[BLOCKED: Cookie/query string data]` guard — strip `?` with `.split('?')[0]` before returning hrefs.

**Why:** without consent+scroll the page returns 0 listings; the mixed number format breaks a single-locale parser; the detail page is too thin to score without the source, and the source resolves only via the hidden `data-href`.
